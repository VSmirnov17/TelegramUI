# Next 15 / React 19 runtime integration

This isolated JavaScript App Router consumer tests Next **15.5.28** and React / React DOM **19.2.9** against the library's actual npm tarball. Root development and Storybook remain on React 18. The fixture build skips the root ESLint configuration because it uses the library TypeScript project, which excludes this JavaScript consumer. The fixture and Next dependencies are excluded from the library distribution and root TypeScript compilation.

From the repository root, with Node 20.9+ and the root development dependencies installed:

```sh
npm ci --prefix tests/integration/next15
cd tests/integration/next15
npx playwright install chromium
cd ../../..
npm run test:next15
```

The smoke command:

1. Runs `npm pack`, including the full library prepack build, tests and artifact checks.
2. Runs the fixture's pinned `npm ci`, then installs the temporary tarball with `npm install --no-save --package-lock=false`. This resolves the library's React 19 peers without force or legacy peer flags. It clears the Next compilation cache so an older local archive with the same package version cannot be reused. The lockfile pins the framework and browser tooling; the changing local library artifact is intentionally installed separately rather than committing its archive or integrity hash.
3. Starts Next dev, checks the real HTTP SSR response and imported CSS, then blocks browser scripts to inspect the pre-hydration DOM. It verifies that hydration preserves nodes (including the library `Input` inside a `Cell` and the Cell's text elements, but not the base-only decorative ripple), input contents, focus and selection when Telegram reports iOS/dark or the browser reports dark, after the server rendered base/light.
4. Exercises nested inheritance, explicit overrides, theme changes, typing, clicking, and opening a Modal containing Multiselect fields (full-click selection, default stay-open behavior, opt-in `closeDropdownAfterSelect` closing, portal and focus restoration). The SSR response also includes a Multiselect. It replaces and unmounts callback refs, checking React 19 cleanup callbacks and legacy null notifications through merged library refs. Browser errors and warnings, including React hydration diagnostics, fail the check.
5. Opens a Modal inside a bounded, transformed portal (matching inline Docs), then checks that opening focus preserves both container and page scroll positions, the complete dialog stays visible, and closing restores focus to the trigger (issue #8).
6. Keeps a long-content Modal open while resizing the layout viewport from 320 × 220 to 320 × 568, 414 × 896, 834 × 1112 and back. Checks growing/shrinking height, bottom alignment, preserved dialog identity and draft value, internal scrolling to the final action, closing, and absence of horizontal page overflow (issue #5). The input is blurred before resizing to distinguish this from virtual-keyboard visual viewport behavior.
7. Checks the compiled AppRoot palette in a dedicated `/palette` consumer: both appearances and platforms, with and without Telegram variables and the opt-in `ignoreTelegramTheme` setting (16 combinations). All 15 Telegram-backed library tokens retain their existing defaults or use the incoming values as appropriate. Nested roots inherit the option, explicit false restores Telegram sourcing, inline library token overrides survive, SDK variables remain untouched, and a real Popper portal inherits its owning root.
8. Reads actual SegmentedControl track, selected segment and Caption colors before hydration, after hydration and after Telegram `themeChanged` / browser theme changes. A scoped dark SDK palette verifies that first-paint surfaces match the already-dark text even while automatic SSR context is light. Four explicit base/iOS × light/dark roots check defaults independently. The probe preserves server DOM and focused buttons, exercises all periods and slider movement, checks selected Caption typography, and keeps focus and selection through theme changes (issue #7).
9. Opens an isolated `/tabbar-layout` full-page consumer so its fixed panel cannot cover the existing form/Modal fixture. Native tab clicks switch the rendered page and selected styles with focus preserved. Real document wheel scrolling must reveal the final action completely above the bar before clicking. The same forwarded-ref node stays fixed at the viewport bottom while label, platform and bound safe-area CSS-variable updates change its measured border-box height and reserved content padding. Checks official-variable precedence over SDK aliases, explicit zero and no doubled inset, both appearances/platforms, and 320 × 568, 414 × 896 and 834 × 1112 viewport changes. These are simulated bound CSS values, not physical Telegram safe-area or keyboard tests (issue #18).
10. Uses `/modal-close` to verify uncontrolled async self-close through the ref forwarded to the actual native Close button. Deferred saves remain open while pending, rejection permits retry, and success clicks the native close path once. Checks Enter/Space activation, focus restoration, independent nested ownership, and a controlled modal that remains open until its owner applies the requested change. Child and dialog refs keep their DOM identity during state changes; callback-ref cleanup runs once through the slot with the child's own ref intact. Repeats on both platforms and appearances (issue #20).
11. Checks `/font-family` at 320 × 568 against the compiled public CSS: global AppRoot and scoped Section font tokens reach actual Banner/Button/Section text, while a default sibling stays unchanged and ordinary parent `fontFamily` reproduces the reported limitation. Inspects server CSS before hydration, preserves the focused Button through hydration, then verifies actual Tooltip Caption fonts in their AppRoot portal and with an explicit scoped token class. Native click/Enter/Space preserve trigger focus and the tooltip description relationship across both platforms and appearances. Triggers and their complete labels must fit the viewport and clipping ancestors; a library List stacks the scoped probes. Generic font families test CSS family resolution; this does not test downloading a custom font (issue #13).
12. Checks native date inputs at `/date-input` using actual compiled `color-scheme` styles before hydration, after automatic Telegram/browser dark detection and after a light theme change. Four explicit platform/appearance roots check date schemes independently. Both inline scheme overrides remain effective and text inputs retain their original scheme. Native date edits, bounds, forwarded focus refs, DOM identity and focus survive hydration/theme changes (issue #3). This does not emulate a physical mobile picker.
13. Stops dev, builds Next production and repeats the same browser checks with `next start`.

The fixture starts at a 414 × 896 browser viewport and changes size for the Modal regression. It verifies framework runtime integration, not the Storybook visual matrix. No library components or styles are changed by this fixture. Its JavaScript consumer does not establish React 19 TypeScript declaration compatibility. The library `Input` inside a `Cell` is the hydration probe: it must keep its DOM node, value, focus and selection when the platform changes from base to iOS, and a controlled `Input` in a `Cell` must keep focus on every keystroke.

Set `NEXT15_PORT` to change the default port 3105. A separately provisioned Chromium can be selected with `PLAYWRIGHT_EXECUTABLE_PATH`; `PLAYWRIGHT_NO_SANDBOX=1` is available for isolated CI containers that require it. Browser system libraries still need to be available (see Playwright's `install --with-deps` option). The runner stops its server/browser and removes the temporary tarball on success or failure.

Set `NEXT15_ARTIFACT_DIR` to save the font-family and date-input probes' computed-style evidence, plus font-family screenshots with a scoped Tooltip open.
